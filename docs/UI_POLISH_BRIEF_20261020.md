## 二、文字过多的真实原因（已量化）

我把每页可见中文逐页统计：

| 页面 | 中文字数 | 卡片数 | 判断 |
| :--- | ---: | ---: | :--- |
| device | 119 | 2 | 尚可 |
| unlock | 164 | 2 | 偏多 |
| spoof | 174 | 4 | 偏多 |
| power | 181 | 2 | 偏多 |
| **dlss** | **298** | 5 | **最重** |
| overlay | 171 | 3 | 偏多 |
| dualgpu | 136 | 6 | 尚可 |
| **maintenance** | **261** | 4 | **次重** |
| logs | 100 | 5 | 好 |
| **update** | **203** | 3 | 偏重 |

文字多不是因为句子长，是**四种东西本不该出现在 UI 上**：

### 2.1 卡片标题带序号（22 处）

现在是「1. 运行库状态与镜像源」「2. 目标游戏目录与劫持选项」「3. 部署前置检查结果」……

**这是说明书的写法，不是软件的写法。** 22 处全部去掉序号，只留名词短语。

```
改前：1. 运行库状态与镜像源 (dlss.state)
改后：运行库
```

### 2.2 接口名 / 字段名直接当文案（17 处）

这是最严重的一类——把实现细节印在界面上：

| 现在界面上写着 | 问题 |
| :--- | :--- |
| `(dlss.state)` `(spoof.state)` `(overlay.state)` `(update.state)` | 内部消息名 |
| `(options: optLevel / maxFrames / engine / preset / srMode)` | JSON 字段名 |
| `(spoof.models.groups)` `(factory.reset)` `(unlock.install)` `(unlock.rollback)` `(spoof.apply)` `(power.setPreset)` `(overlay.restore)` | 动作名 |
| 表单标签 `gameDir` / `proxyName` | 字段名 |
| 表头 `槽位(slot)` / `物理型号(detectedModel)` / `当前描述(currentDesc)` / `目标伪装(targetName)` | 字段名 |
| 按钮 `暗色主题 (dark)` / `自动备份 (auto)` / 出厂基线 (factory) / 手动创建 (manual) | 枚举值 |

**全部改成中文。** 需要技术信息时放在 `title` 属性里（鼠标悬停才看得到），不要印在脸上。

### 2.3 中英混排

`MODULES (10)`、`DEVICE`、`System & Flags`、`Theme & perf-low`、`WAL 事务快照`。

规则：**面向用户的文字只用中文**。产品名 `CMP 90HX`、`PCIe`、`DLSS`、`UEFI`、`HAGS`、`Alt+Z` 这类专有名词保留，其他一律中文。

### 2.4 一句话塞三件事

现例：「WAL 事务快照时间线、注册表与 BCD 备份还原点管理、界面性能模式与危险区出厂重置」

规则：**页面副标题 ≤ 14 字**，只说这一页干什么，不列功能清单。卡片不要副标题，标题自解释。

## 三、界面「难看」的具体成因（我逐页截图看过）

### 3.1 重复信息占位

- 左下角「当前显卡 / CMP 90HX / BUS: 0000:01:00.0」与首页 hero 区的 `CHIP/ID/VRAM/DRV/BUS` 标签**完全重复**
- 首页 hero 右侧一排等宽小字 `CHIP: GA102  ID: 10DE:220D  VRAM: 10GB GDDR6X  DRV: 616.92  BUS: 0000:01:00.0` —— 像调试输出

**改法**：hero 区只留「显卡名 + 2 个最关键标签」，其余进详情表；左下角侧栏只留一行极简状态（或直接删）。

### 3.2 仪表盘拥挤

四张仪表卡里，大数字和单位、次要信息挤在一行：

```
62°C          148.5W          1024MB
高温 95°C / 关机 98°C   当前墙 300W / 默认 250W   核心 1710MHz / 显存 9501MHz
```

**改法**：主数值一行（大号 + 小号单位），标签一行（12px 灰），次要信息**默认不显示**，hover 或用 `⋯` 展开。

### 3.3 3D 显卡上压着小字

hero 右侧 3D 模型图上压着「点击展开/合拢 3D 透视结构」，破坏画面。

**改法**：移到图下方，或做成 hover 才出现的提示。

### 3.4 字号层级不统一

我扫到 `10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5` 六种字号混用。

**改法**：收敛到 **4 级**——标题 14 / 正文 12.5 / 次要 11.5 / 大数字 24~28。其余一律不许出现。

### 3.5 次要文字对比度偏低

`--text-muted: #64748b` 在 `#07090e` 底上偏暗，小字看着累。

**改法**：深色主题下次要文字提到 `#94a3b8`，正文 `#cbd5e1`。

## 四、深度打磨：UI / 动效 / 细节

> 这一节是用户明确要求的「深度做一下细节、动画、ui、动效」，不是可选项。

### 4.1 间距节奏

- 全站用 **8px 栅格**：4 / 8 / 12 / 16 / 24 / 32，禁止 5px、7px、13px 这类随意值
- 卡片内边距统一 **16px**
- 卡片之间 **12px**，分组之间 **24px**
- 内容区左右留白 **24px**（现在 22px）

### 4.2 动效统一

所有过渡用同一条曲线，三档时长：

```css
--ease: cubic-bezier(0.2, 0.8, 0.2, 1);
--t-fast: 120ms;   /* hover / 按下 */
--t-mid:  180ms;   /* 展开 / 折叠 / 弹窗 */
--t-slow: 240ms;   /* 页面切换 */
```

禁止 400ms 以上；禁止弹跳缓动。

具体的动效清单：

| 场景 | 做法 |
| :--- | :--- |
| 页面切换 | 内容 `opacity 0→1` + `translateY 8px→0`，160ms |
| 卡片 hover | 边框提亮 + `translateY(-1px)`，**不得改变占位尺寸** |
| 按钮按下 | `scale(0.98)`，100ms |
| 数值刷新 | 数字 `opacity` 抖动一次（120ms），禁止整块重排 |
| 仪表环 | 弧长变化 300ms 缓动，不要瞬跳 |
| 进度条 | 宽度过渡 200ms，百分比数字同步 |
| Toast | 从右下角滑入 12px，240ms |
| Modal | 背景淡入 120ms，面板 180ms 缩放 0.98→1 |
| 骨架屏 | 1.4s 循环微光，不要闪烁 |

### 4.3 一屏只留一个持续动画

现在首页同时跑：背景粒子 + 3D 旋转 + 仪表弧光 + PCIe 脉冲。CPU 实测占 **24% 单核**（无视频输出环境下）。

**改法**：默认只保留 3D 旋转或粒子其中**一个**持续动画；另一个改为 hover/点击触发。`perf-low` 下两者都停。

### 4.4 交互细节

- 所有可点元素必须有 `:focus-visible` 焦点环（现在没有）
- 所有按钮的 `:active` 状态（现在只有 hover）
- 表格行 hover 高亮
- 滚动区域隐藏滚动条后，必须在顶部/底部加极淡渐隐提示「还有内容」
- 空态必须有图标 + 一句说明 + 一个下一步按钮（现在部分页面只有一行灰字）
- 危险按钮（出厂重置）hover 时不要发光闪烁，改为边框加重

### 4.5 视觉一致性

- 卡片圆角统一 12px（现在有 10/12/14 混用）
- 图标尺寸统一 14 / 18 / 22 三档（现在 13/14/16/17/22 混用）
- 所有「标签 pill」高度统一 20px，字号 11px
- 分割线只用一种：`1px rgba(255,255,255,0.06)`，深色下不提亮

### 4.6 图标系统（现在是弱项）

**现状实测**：全文 120 个内联 SVG，但**只有 1 个用了渐变填充**——说明绝大多数是单色线条，没有层次；尺寸上 13px × 2、14px × 10、其余走 `.svg-icon` 默认 17px，三四种规格混着。

要求：

1. **统一规格**：全部 `viewBox="0 0 24 24"`、`stroke-width: 1.75`、`stroke-linecap/join: round`
2. **双色法**：每个图标 = 主体描边（`currentColor`）+ 一处 10% 透明度填充块。选中/激活态填充提到 18% 并换成主色。这样一屏里能看出层次，现在全是细线太平
3. **尺寸三档**：按钮内 14 / 独立图标 18 / 页面标题 22。**禁止 13、16、17 这类中间值**
4. **14px 可辨识**：先把图标缩到 14px 看还能不能认出来。现在侧栏有几个图标（芯片、PCIe、矩阵）在 14px 下细节糊成一团，需要减笔画——**少画一根线比多画一根线难，但必须减**
5. **光学对齐**：图标视觉重心对齐按钮中心，不是几何中心。带圆形的图标要略上移 0.5px
6. **语义唯一**：同一个意思只能有一套画法。「解锁」「伪装」「覆盖」这类重复出现的概念，全站共用同一图标，不许换着花样画
7. **禁用 emoji**，禁用字符符号（`✓` `×` `⋯` 除外，且必须用 SVG 画）

建议为侧栏 10 个模块各定一个「一眼可辨」的主图形，其余细节全部砍掉。

### 4.7 3D 显卡模型（重点打磨）

**现状**：5 层 CSS 3D——背板、散热鳍片、顶部灯条 + 双 8-pin、IO 挡板、正面双风扇，hover 旋转、点击拆解。

问题：层次有了，但**材质感和光影不够**，看起来像几个色块叠在一起。

要求：

1. **材质**：
   - 金属边框用 `conic-gradient` 做拉丝高光（斜向 45°，明暗交替 6 段）
   - 风扇叶片用 `radial-gradient` 做根部到叶尖的明度渐变
   - 灯条用一条 2px 的发光条，颜色取 `--accent`，不要整块发光
2. **光影**：
   - 顶部加一层环境光（伪元素，`linear-gradient(to bottom, rgba(255,255,255,0.06), transparent)`），**不要堆 drop-shadow**
   - 模型下方加一条极淡的椭圆投影，制造落地感（现在模型是"浮"着的）
3. **风扇**：9 片叶片要画满 9 片且等分；转速与 `sensors.tick.fanPercent` 挂钩（P4 会推），静息时慢转（约 6s/圈），高负载加速
4. **拆解动画**：分层 Z 轴位移**错开时序**（每层 40ms stagger），不要 5 层同时弹开；收起时反向
5. **旋转**：限制在 ±25°，带阻尼跟随鼠标，**不要整屏跟随**（现在的幅度过大，容易晕）
6. **细节**：8-pin 供电要能看出 4+4 分针并分色；IO 挡板要有开孔阵列；固定螺丝要有十字纹
7. **渲染成本**：这套模型在软件渲染下要能降到静态倾角（`perf-low` 已有），并且**不得成为每帧重绘的元凶**

### 4.8 整体质感

- 卡片顶部加 1px 内高光 `inset 0 1px 0 rgba(255,255,255,0.06)`，制造亚克力边缘感
- 深色主题不要用纯黑大色块，底色保持 `#07090e` → `#0d1117` 的极淡径向渐变
- 主按钮的渐变方向统一 135°，且只允许两种（主色、危险色）
- 所有"发光"效果限制在 3 处以内（现在是卡片 hover、按钮、灯条、粒子、仪表弧光都在发光，互相打架）

## 五、不能破坏的东西（违反即退回）

1. **`data-action` 的值一个字符都不能改** —— 宿主 C# 侧按这些字符串路由
2. **`id` 属性不许改** —— 渲染逻辑与宿主校验都依赖它们
3. **契约字段名不许改**（`device.snapshot` / `sensors.tick` 等 payload 内部的 camelCase 键）
4. **保持单文件**：零外链、零 `<img>`、零 CDN、零第三方库、零 webfont
5. **保持 `body.perf-low` 降级可用**，降级后界面必须完整、不塌
6. **保持 10 页结构**与现有 `[data-page]` 值
7. **不许用 emoji 作图标**，全部内联 SVG
8. **不许关闭 `MOCK` 看门狗**（宿主无响应时 800ms 后仍要能显示演示数据）
